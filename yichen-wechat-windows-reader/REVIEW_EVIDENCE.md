# Repository evidence matrix

This file records evidence present in the committed tree. It does **not** claim that a GitHub Actions run exists or has passed. A reviewer must inspect the specific run separately and match its asserted `HEAD` to the revision being reviewed.

| Requirement | Implementation evidence | Committed static/synthetic evidence |
|---|---|---|
| Experimental, bounded compatibility claim | `SKILL.md` and `README.md` limit support to schema variants accepted by the validator and covered by synthetic fixtures | No real Weixin database, binary, key, or user chat fixture is included; broad real-world compatibility is explicitly not claimed |
| No process memory, keys, discovery, decryption, UI control, or network | The feature ships one production entry point, `scripts/snapshot_reader.py`, whose CLI requires `--snapshot`; exclusions are explicit in `SKILL.md` | `tests/test_snapshot_reader.py` inventories the production script boundary and scans for prohibited extraction/decryption interfaces |
| Explicit snapshot scope; authorization and detachment are caller preconditions | The CLI has no discovery/config fallback; validation rejects UNC/network roots, unsafe link/reparse paths, and child targets outside the supplied root | `SKILL.md` requires current-task authorization and a detached static snapshot; synthetic fixtures exercise an explicit independent path and adversarial link escape. The validator does not prove ownership or acquisition history |
| Read-only input; checkpointing is a caller precondition | SQLite opens through `mode=ro&immutable=1` plus `PRAGMA query_only=ON`; validation rejects relevant WAL/SHM/journal sidecars but cannot prove prior checkpoint history | Synthetic tests compare input bytes, exercise SQLite write denial, and reject a snapshot with a WAL sidecar |
